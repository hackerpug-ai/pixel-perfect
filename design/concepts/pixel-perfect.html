pixel-perfect is an agent skill that reads every frame of a high-fidelity mockup and turns it into real components in your framework: tokens, atoms, molecules, organisms, and screens. Each layer is checked against the frames it came from before the next layer starts.

Why it exists

Designs die in translation.

AI can draw a gorgeous dashboard in seconds. Someone still has to read that picture and write the code. Spacing gets eyeballed, colors get hardcoded, and the same card gets built four times with four different paddings.

Six weeks later nothing matches what was approved, and nobody can say what correct would look like. There was only ever a picture of a system.

  1. 1

    Padding 20 → 14. Measured by eye from a screenshot.

  2. 2

    Button color typed by hand. The accent token existed. Nobody used it.

  3. 3

    Corner radius 12 → 6. Copied from a card on another page.

  4. 4

    Avatars at 24, 22, and 28 px. This is the fourth copy of the card, and each copy differs.

Generating a design is the easy half. pixel-perfect does the other half: it turns the design into a system you can build on and keep.

Input

Designs go in as references

Point it at a Claude Design deck, an HTML export, a URL, a screenshot, or a wireframes folder. It renders every frame, reads them once, and writes an inventory of what to build. The frames stay on as pixel targets.

design/inventory.json
Order

Layers are built in order

Tokens first, then atoms, molecules, organisms, and screens. Every layer has a gate, so a screen is never built on an atom that doesn't render.

gates
Upkeep

The system stays maintained

A manifest records what exists, what passed, and which library each component wraps. Later changes run back through the same gates, so the system doesn't drift.

design/manifest.json
Sandbox

A component browser in any stack

It generates a sandbox in your own framework, from React and SvelteKit to Expo, SwiftUI, GPUI, and Ratatui. Storybook is there if you want it.

npm run sandbox

Use

From mockup to system in four commands

Commands are shown in Claude Code syntax. In Codex, use $pixel-perfect:init. In Cursor and OpenCode, use /init. In Pi, use /skill:pixel-perfect-init.

  1. Step 1

    Describe the project

    /pixel-perfect:init

    It asks for the goal, the vibe, your platforms, framework, style system, and component library. List your designs as references. They stay where they are; nothing is copied or converted.

    design/manifest.json
    {
  "goal": "Deploy dashboard for small platform teams",
  "vibe": "calm, dense, high-contrast",
  "references": [
    "design/harbor-deck.html",
    "design/screens/mobile-list.png"
  ],
  "platforms": {
    "web-desktop": {
      "tools": {
        "framework": "vite",
        "style": "tailwind",
        "components": "shadcn",
        "sandbox": "custom"
      }
    }
  }
}
  2. Step 2

    Set up the bench

    /pixel-perfect:scaffold

    It installs your tools, writes the theme, and generates a sandbox in your framework with a story for every token. A hello-world component has to render before anything else gets built.

  3. Step 3

    Separate, confirm, build

    /pixel-perfect:build

    It renders every frame of your designs, reads them once, and writes an inventory of the atoms, molecules, organisms, and screens to make, each tied to the frames that justify it. You confirm the inventory once. Then it builds each layer against those frames, and each gate has to pass before the next layer starts.

    design/inventory.json · excerpt
    "molecules": [
  {
    "name": "DeployRow",
    "composes": ["Avatar", "StatusBadge"],
    "states": ["live", "building", "failed"],
    "appears_on": ["harbor-deck/03", "harbor-deck/07"],
    "evidence": "Deploy list rows on desktop and mobile frames"
  }
]
  4. Step 4

    Check the proof

    /pixel-perfect:status

    It shows phase progress, gate results, drift between each component and its captured reference, and inventory no screen uses anymore. /pixel-perfect:verify re-runs the current gates whenever you want evidence.

After the first build

Keep the system alive

/pixel-perfect:refine

Change how an existing component or screen is built. The gates it touches run again.

/pixel-perfect:evolve

Change what exists. Absorb a new screen or mock, promote a repeated pattern into a component, or remove a screen and sweep up what only it used.

/pixel-perfect:add-platform

Add iOS, Android, or another target without resetting the platforms you already have.

/pixel-perfect:wireframe

No mockup yet? Turn a PRD into ASCII wireframes. Build reads them the same way it reads a high-fidelity design.
