# Technical Risks

| ID | Lens | Risk |
|----|------|------|
| R-allowlist | Actions | The fix-diff allowlist stays harness/*.json and skills/** relative to plugins/pixel-perfect/. Research on 2026-10-06 said behavior fixes would land in workflows/ and scripts/adapters/, and that finding was not re-checked. Those paths are not added. A newest failure whose real edit is under workflows/ or scripts/adapters/ is rejected by the patch recheck and does not become a pull request. The push path filter may still include scripts/adapters/** so those changes are graded. That does not admit them into the fix diff. |
| R-cursor-key | Actions | harness-smoke has keys for Claude, Codex, Grok, Pi, and OpenCode, and no Cursor key. Cursor is one of the six harnesses. Add one Cursor credential to harness-smoke only, on the Cursor smoke steps, under the variable the CLI-invocation lens uses. Do not put it in ci.yml, heal-agent, or heal-pr. Until it exists, Cursor cells are could-not-run with reason missing-key, the run fails closed, the release is refused, and no fix pull request is opened for that missing key. |
| R-push-main | Actions | The owner added a push-to-main trigger. The October 2026 security review forbade pull_request and pull_request_target, and that ban stays, including workflow_run. Smoke secrets run only for schedule, dispatch on main, and push to main in hackerpug-ai/pixel-perfect with the plugin path filter. A fork pull request does not start this workflow. The risk is a later edit that adds a pull-request event, drops the main-branch guard, or widens the path filter to the whole repo. That would expose harness-smoke keys to an untrusted pull request or spend them on changes that are not the plugin. The push filter must not be copied onto the fix-diff allowlist. |
| R-probe-retention | Actions | Since 2026-10-01, workflow runs, commit statuses, and artifacts share the Actions retention window, at most 90 days on a public repository. The release gate reads harness-eval/pinned and artifact harness-eval-result. When that window passes, the probe is missing and publish is refused. That is fail closed. There is no older 400-day status to fall back on, and a green ci.yml run is not a substitute. |
| R-exit-zero | Harness | Exit code 0 is not success. Claude Code reported success with every required read denied. Pi JSON mode exits 0 when the model call fails. Codex warnings use type error while the process exits 0. A grader that keys off the exit code, a Claude success subtype, or every Codex error event will hide a broken run or fail a warning. |
| R-cursor-unproven | Harness | Cursor's headless command was assembled from flags and never run. There is no Cursor CLI on the maintainer Mac. Installing it there is forbidden because the installer relinks ~/.local/bin/agent, which is Grok. There is no no-model command list. The only assembled run uses --trust and --force, which this design does not adopt. Until a runner trial exists under a recorded stance, every live Cursor grade is could-not-run. CURSOR_API_KEY is not in the harness-smoke environment, and a missing key must not look like a pass. |
| R-linux-unproven | Harness | Nothing in this design has been run on Linux. Every Linux install line is unproven. A Mac result must not be copied forward as a Linux pass. Codex on a hosted runner also needs unprivileged user namespaces, or the sandbox can fail closed. |
| R-claude-reads | Harness | With the default permission mode, Claude Code denied reads of its own workflow files, including workflows/RUNTIME-CONTRACT.md and workflows/status.md, and still reported success. --add-dir is untested. -p can skip plugins in bare mode. The assembled Bash(node *) allow list does not show that reads succeed. A denied read is not a pass, and a missing plugin is could-not-run rather than a plugin behavior fail. |
| R-grok-trust | Harness | The checkout install command includes --trust, and --trust is forbidden on any step that holds an API key. This Mac's Grok config approves every tool call, so a runner that copies that config would hide permission failures. bypassPermissions is not the stance. |
| R-opencode-layout | Harness | OpenCode's slash form does not run headless. Published install clones the whole repo into the work directory, so fixture expectations sit beside the agent once a tag contains them. The checkout install command is unknown. The channel for --platform web-desktop is unknown, so verify cannot be graded yet. The reply field name is unknown. Every run leaves a session, and that residue is not a grade. opencode debug config prints provider config and must not run in a step that holds a key. |
| R-list-count | Harness | Claude Code, Codex, and Grok list more than the 11 public commands. A check that requires a length of exactly 11 will fail a good install. Cursor has no no-model list, and substituting a model call would break the no-model rule. |
| R-question-signal | Harness | Grok and Cursor tell the model to continue after a question, and Claude Code must not use turn-end as the question signal either. Waiting for the process to exit grades work the harness told the model to do after the question. List, status, and verify must ask nothing; the separate must-ask probe stops at its first question, and the untested resume path must not be used to answer them into a pass. |
| R-resume-untested | Harness | The one phase-two answer path is resume-with-text on every harness. It has not been run on any harness, and the evidence does not assign --resume, exec resume, --session, or --continue to a named CLI. Inventing an argv would be a stub. |
| R-codex-cache | Harness | Codex runs skills from ~/.codex/plugins/cache/pixel-perfect/pixel-perfect/<version>, not from the working tree. A checkout grade can execute a stale cache and answer the wrong question about whether our change broke Codex. |
| R-pi-model-call | Harness | Pi's own pixel-perfect status has not been run. Pi 1.0.x is outside the surveyed 0.84.4 behavior and requires --model. JSON mode exits 0 when the model call fails. Pi waits on stdin, so an unclosed stdin hangs until timeout. Pi has no permission gate, so a runner isolation failure is outside Pi's own flags. |
| R-verify-report | Harness | The evaluator must produce the exact case-declared report from observed verify evidence. Plugin output alone need not create the file. Metadata, unrelated files, and stale reports cannot prove detection; the real producer and path checks remain unverified. |
| R-status-migrate | Harness | Status must not migrate. Seeded factual output and unchanged hashes are both required; generic text fails. Real two-fixture evidence is still required. |
| R-no-wall-clock | Harness | No harness has a wall clock. Cursor headless runs have hung in GitHub Actions before. A call without a closed stdin and an outer timeout can sit forever and never become a grade. A turn cap is not a substitute, and hitting one is not success. |
| R-stance-open | Harness | Approve-everything is named and not adopted. Codex read-only versus workspace-write is the only capability split this design requires. The other harness stances are candidates. A model run before security records a stance is could-not-run, not a silent bypass. |
| R-mode-mixup | Harness | Published mode and checkout mode answer different questions. Grading a tag clone when the question is our commit, or grading the workspace when the question is a new harness release, blames the wrong change. OpenCode checkout cannot be graded until a real command exists. |

## Remediation proof boundary

Version 1.0.1 resolves the written contracts, not their runtime proof. Direct fixer authentication, bot merge refusal, six-harness stream mappings, structural-only live verify, loaded-byte identity, and persistent resume remain implementation gates. Scheduling delays create no synthetic success. Release authority expires after 36 hours regardless of 90-day retention. See [remediation record](../11-remediation.md).
